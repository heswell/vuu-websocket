## What is measured

- **SortBenchmarkRunner.sortLargeTableSingle**
  - Scala: Sort.doSort of all primary keys by exchange (unique strings) ascending.
  - vuu-viewport: InMemoryViewport created over the table (filter, sort, group build and first 50 row window), as for CREATE_VP.
- **SortBenchmarkRunner.sortLargeTableMulti**
  - Scala: Sort.doSort of all primary keys by exchange descending, close ascending.
  - vuu-viewport: InMemoryViewport created over the table (filter, sort, group build and first 50 row window), as for CREATE_VP.
- **FilterBenchmarkRunner.equalsFilter**
  - Scala: EqualsClause.filterAllSafe on exchange, which is an indexed column (indexFields), so this is an index lookup.
  - vuu-viewport: InMemoryViewport created over the table (filter, sort, group build and first 50 row window), as for CREATE_VP. No column indexes, so a full scan.
- **FilterBenchmarkRunner.startsWithFilter**
  - Scala: StartsClause.filterAllSafe on exchange.
  - vuu-viewport: InMemoryViewport created over the table (filter, sort, group build and first 50 row window), as for CREATE_VP.
- **FilterBenchmarkRunner.lessThanFilter**
  - Scala: LessThanClause.filterAllSafe on close.
  - vuu-viewport: InMemoryViewport created over the table (filter, sort, group build and first 50 row window), as for CREATE_VP.
- **TreeBenchmarkRunner.treeLargeTable**
  - Scala: TreeBuilder.buildEntireTree, group by exchange (one group per row), no aggregations, all nodes collapsed.
  - vuu-viewport: InMemoryViewport created over the table (filter, sort, group build and first 50 row window), as for CREATE_VP.
- **JoinTableBenchmarkRunner.iterateRows**
  - Scala: pullRow for every key of orderPricesCurrencies (orders join pricesCurrencies join currencies). Join rows are assembled on read.
  - vuu-viewport: getRowAtKey for every key of the JoinTable. Join rows are materialized, so this is a key lookup.
- **InMemDataTableBenchmarkRunner.iterateRows**
  - Scala: pullRow for every primary key of prices.
  - vuu-viewport: getRowAtKey for every key of prices.
  - Note: the JMH loop calls keys.size() on every iteration and TablePrimaryKeys (a Scala Iterable) computes size by walking every key, so the Scala time is O(n^2) and mostly benchmark overhead. Only sizes up to 50,000 are run on the Scala side.
- **InMemDataTableBenchmarkRunner.updateRows**
  - Scala: pullRow then processUpdate of the same row for every key, running the join provider every 16384 rows.
  - vuu-viewport: Copy of each row upserted, join tables updated synchronously.
- **InMemDataTableEmptyBenchmarkRunner.addRows**
  - Scala: Build and processUpdate N price rows. The table persists across invocations, so after the first invocation these are updates of existing keys.
  - vuu-viewport: Build and upsert N price rows into the same persistent table.
- **InMemDataTableRemovalBenchmarkRunner.removeRows**
  - Scala: processDelete of N keys (untimed re-insert before each invocation), running the join provider every 16384 rows.
  - vuu-viewport: delete of N keys (untimed re-insert before each invocation), join tables updated synchronously.
  - Note: Scala removes each key from the primary key array with a linear indexOf, so deletes are O(n) each and the benchmark is O(n^2) on that side.
