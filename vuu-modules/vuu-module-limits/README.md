# @heswell/vuu-module-limits

Reusable Vuu server module for trading limit definitions. Limits are added,
changed and deleted in session tables, and saved changes take effect on the
next business day.

| Table                            | Key         | Purpose                                            |
| -------------------------------- | ----------- | -------------------------------------------------- |
| `LIMITS.limitDefinitions`        | `limit_key` | One row per limit, editable through session tables |
| `LIMITS.edit-limitDefinitions`   | `limit_key` | Blueprint: the columns a user enters, `editChange` |
| `LIMITS.import-limitDefinitions` | `limit_key` | Blueprint: as edit, plus the CSV row `vuuRowNum`   |
| `LIMITS.export-limitDefinitions` | `limit_key` | Blueprint: every column                            |

## Usage

```ts
import { createVuuServerApplication } from "@heswell/vuu-server";
import { LimitsModule } from "@heswell/vuu-module-limits";

const application = createVuuServerApplication({
  // ...
  modules: [LimitsModule()],
});
```

Options:

| Option      | Default  |
| ----------- | -------- |
| `namespace` | `LIMITS` |

## Behaviour

- **Editing.** A client creates a session table with `createSessionTable`
  on a `limitDefinitions` viewport, `sessionType` `edit`, `import` or
  `export`. `limit_key` is generated by the server when a row is added.
  `entity_id`, `metric`, `scope` and `period` can only be set when a limit
  is added. Values are checked as they are entered.
- **`editChange`**, in an edit session, is maintained by the server and
  cannot be edited. It describes the change saving each limit will make,
  including changes already held: `New limit`, `Delete`, or each changed
  value in column order, e.g. `soft changes to 95, hard changes to 150`.
- **Saving** is all or nothing. If any limit is not valid, nothing is
  saved, each invalid limit has its `vuuMsg` set, and the save fails with a
  message naming them, by `limit_key`, or by line for an import.
- **Next business day.** A new limit is saved as `Pending`. A change to, or
  deletion of, an `Active` limit is held, and the limit is `Pending`.
  `change` is set to the limit's `editChange` from the session. When a new business day begins (Saturday and Sunday
  belong to the Friday before), Pending limits become `Active` with their
  held changes applied. `changed_by` is the user who saved the change.
- **`activatePendingLimits`** RPC, on a `limitDefinitions` viewport,
  activates Pending limits at once, as at the start of the next business
  day. For demos and tests.

Limits are held in memory, and the server starts with none.

## Reference data

Entities, metrics with the periods each allows, and currencies are defined
in `src/referenceData.ts`. A client offering these values in its editors
must use the same values.

## Packaging conventions

- The module is a factory function, with a namespace option, so different
  applications can assemble it.
- `@heswell/vuu-server` and `@heswell/vuu-table` are peer dependencies.
